=========
1. Общее
=========

1.1. Назначение
===============

Учебный маркетплейс. Площадка, где администратор выставляет
товары, а покупатели их просматривают и оформляют заказы.

Проект создаётся для практики веб-разработки на чистом Python
и JavaScript без внешних библиотек и фреймворков.

1.2. Границы проекта
====================

В рамках проекта **не реализуется**:

* приём платежей;
* загрузка изображений (только URL на внешний ресурс);
* подтверждение email, восстановление пароля;
* модерация товаров и отзывы;
* сложный поиск с фильтрами и сортировками;
* мобильное приложение;
* реальные продавцы (товары создаёт только администратор).

1.3. Целевая аудитория
======================

* **Гость** - неавторизованный посетитель.
* **Покупатель** - зарегистрированный пользователь.
* **Администратор** - управляет каталогом товаров.

Авторизация будет добавлена отдельным этапом.


=================
1. Технологии
=================

2.1. Backend
============

* Python 3.10+;
* только стандартная библиотека:

  * ``wsgiref.simple_server`` - WSGI-сервер для разработки;
  * ``sqlite3`` - база данных;
  * ``json`` - сериализация API;
  * ``hashlib``, ``secrets``, ``hmac`` - пароли и сессии;
  * ``http.cookies`` - разбор и формирование cookie;
  * ``urllib.parse`` - разбор query-строки;
  * ``mimetypes`` - отдача статики.

2.2. Frontend
=============

* HTML5;
* CSS3 (без препроцессоров);
* JavaScript (ES-модули, без фреймворков и сборщиков);
* ``fetch`` для обращения к API.

2.3. Хранение данных
====================

* SQLite, файл ``data/marketplace.db``;
* схема описана в ``backend/db/schema.sql``;
* миграции не используются - только ``CREATE TABLE IF NOT EXISTS``.


========================
3. Архитектура
========================

3.1. Разделение на слои
=======================

::

    marketplace/
    ├── backend/        # Python: WSGI, роутер, API, БД
    ├── frontend/       # HTML/CSS/JS: SPA
    ├── data/           # SQLite-файл
    └── run.py          # точка входа

Backend и frontend **не знают** друг о друге, кроме контракта
REST API. Backend отдаёт JSON, frontend - статику.

3.2. Backend: слои
==================

* ``core/``  - инфраструктура (Router, Request, Response, WSGI-app).
* ``api/``   - HTTP-обработчики, по одному модулю на ресурс.
* ``db/``    - подключение, схема, репозиторий (все SQL-запросы).
* ``routes/``- регистрация маршрутов.

3.3. Frontend: слои
===================

* ``index.html`` - единая точка входа;
* ``js/api.js``  - обёртка над ``fetch``;
* ``js/app.js``  - роутинг и инициализация;
* ``js/pages/``  - по модулю на страницу.


========================
4. Функциональные требования
========================

4.1. Гость
==========

* Просматривать список товаров.
* Просматривать карточку товара.
* Искать товары по названию.
* Просматривать категории.

4.2. Покупатель
===============

Всё, что умеет гость, плюс:

* Добавлять товар в корзину.
* Менять количество товара в корзине.
* Удалять товар из корзины.
* Оформлять заказ.
* Просматривать историю своих заказов.
* Просматривать детали заказа.

4.3. Администратор
==================

Всё, что умеет покупатель, плюс:

* Создавать категории.
* Создавать товары.
* Редактировать товары.
* Удалять товары.
* Просматривать все заказы.

1. Этапы разработки

8.1. Список этапов
==================

1. Каркас WSGI + роутер + Response.

10. Статика: отдача файлов из ``frontend/``.

12. Сидирование тестовыми данными.

========================
9. Нефункциональные требования
========================

9.1. Код
========

* Только стандартная библиотека Python.
* Никаких внешних JS-зависимостей.
* Один файл - одна ответственность.
* Никаких «магических» чисел и строк: все константы - в ``config.py``
  или именованы рядом с местом использования.
* Комментарий над каждым классом и каждым методом.
* Комментарии начинаются с глагола.

9.2. Производительность
=======================

* Не критична: проект учебный.
* Достаточно, чтобы страница списка товаров открывалась < 500 мс
  при 1000 записях в БД.

9.3. Безопасность
=================

* Пароли - только в виде хеша (``hashlib.pbkdf2_hmac``).
* Сессии - подписанные cookie (``hmac``).
* SQL - только параметризованные запросы.

9.4. Совместимость
==================

* Python 3.10+.
* Современные браузеры (ES-модули, fetch, history API).
